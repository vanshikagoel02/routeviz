    🔵 Link State Routing (Dijkstra)

    CN Concept Each router floods the network with its link-state advertisements (LSAs), giving every router a complete map of the topology.

    Once each router has the full topology, it independently runs Dijkstra's shortest-path algorithm to compute the least-cost route to every destination.

    Steps: Initialize source distance = 0, all others = ∞ → Repeatedly select the unvisited router with the lowest tentative distance → Relax its neighbors → Mark as finalized → Repeat until destination is reached → Reconstruct path via predecessor map.

    Complexity: O((V + E) log V) with a binary heap. Converges in one pass — no iterative exchange needed.

    🟠 Distance Vector Routing (Bellman-Ford)

    CN Concept Each router maintains a distance vector: a table of estimated costs to every known destination, along with the next-hop router.

    Routers periodically share their distance vectors with only their immediate neighbors. Each router then updates its own vector using the Bellman-Ford equation: cost(n→d) = min over neighbors k of (cost(n→k) + cost_k(d)).

    Convergence: Iterations continue until no router updates its vector. Good-news propagates fast; bad-news (count-to-infinity) propagates slowly — a key limitation addressed by split-horizon and route poisoning.

    📋 Routing Table

    CN Concept A routing table maps every known destination to the next hop router and the associated metric (cost). Packets are forwarded hop-by-hop using these tables — routers never need the full path, only the next step.

    In Link State, tables are built from Dijkstra's predecessor map. In Distance Vector, they are built from the converged distance vectors.

    🚀 Packet Forwarding

    CN Concept When a router receives a packet, it looks up the destination address in its routing table, identifies the next hop, and forwards the packet on the corresponding link. This is repeated at every router until the packet reaches its destination.

    In this simulator, the packet animates along the pre-computed shortest path, simulating hop-by-hop forwarding.

    ⚠ Link Failure & Recovery

    CN Concept When a link fails, routers that depended on it must find alternate routes. In Link State, a new LSA is flooded and all routers recompute. In Distance Vector, affected routers update their vectors, and convergence must occur again — possibly triggering count-to-infinity if no loop-prevention mechanism exists.

    In this simulator, the failed link is excluded from graph construction before routing is re-run, and a comparison of old vs. new routes is displayed.

    📡 Traceroute (Simulation)

    CN Concept The real traceroute command uses IP TTL fields and ICMP time-exceeded messages to discover intermediate routers on a path. Each packet is sent with increasing TTL values; when a router drops a packet (TTL expired), it sends back an ICMP response revealing its address.

    In this simulator, we reveal hops along the pre-computed shortest path step by step, illustrating the concept of path discovery without actual ICMP mechanics.

    🧪 What-If Analysis

    CN Concept Network engineers routinely test how topology changes affect routing — before making changes in production. This is called what-if analysis or traffic engineering.

    By changing link costs or simulating failures, you can observe whether the optimal path changes, whether the next-hop decision shifts, and whether the destination becomes unreachable — all using the actual routing algorithms.
